# Need Extractor Output Template

Adapt this structure to the user's voice and context. The 7 facets are mandatory — do not change, reorder, or merge them.

---

**1. 表层问题**
[One paragraph restating what the user literally said. Use their own phrasing where possible. No interpretation yet.]

**2. 真实需求**
[One paragraph describing the underlying desire or outcome. Start with: "表面上你在问 X，但实际上你想要的是 Y."]

**3. 隐藏约束**
[Bullet list of 2-4 constraints the user has not stated but that matter. No more than 4.]

**4. 不喜欢的方向**
[Bullet list of 1-3 approaches or architectures to avoid. Include both things they explicitly rejected and things that would technically work but feel wrong.]

**5. 当前核心矛盾**
[A single sentence or short paragraph naming the tension. Start with: "卡住你的核心矛盾是..." This is the most important part of the output — be precise.]

**6. 可以砍掉的东西**
[Bullet list of 1-3 things the user is treating as requirements but can be cut or deferred. Include the reason why each is likely a pseudo-need.]

**7. 下一步只做一件事**
[A single concrete action. Must be completable in one sitting. Start with the action verb, not a lead-in like "my suggestion is to..."]

---

[One-sentence invitation for the user to push back.]

## Adaptation Rules

- Write the 7 facet labels in Chinese — they remain the same across all outputs. The language of the *content* should match the user's language.
- Facets 1 and 2 can be 1-3 sentences each.
- Facet 5 (CORE CONTRADICTION) can be 1-3 sentences — it deserves the most space.
- Facets 3, 4, and 6 should always be bullets, not paragraphs.
- Facet 7 must be exactly one action. If you want to include a backup, put it in parentheses and only when the user might have dependency issues (e.g., "Ask Alice for the design files (or if unavailable, sketch your own wireframe)").
