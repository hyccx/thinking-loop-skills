# Example: Tech Stack Choice Paralysis

## Input

> 我要做一个博客系统，本来想用 Next.js 因为最熟悉，但看到大家都在用 Astro，说博客用 Astro 更好。然后我又想，要不要直接 Hugo 算了反正就是静态站。但又怕以后想加功能不好扩展。我已经纠结两周了，每天打开不同的对比页面看来看去。我感觉到自己不对劲，我到底想要什么？

## Output

**1. 表层问题**
你要做一个博客系统，在 Next.js、Astro、Hugo 之间选择困难，已经纠结了两周无法推进。

**2. 真实需求**
你想要的不是"选一个最好的框架"，而是**开始写博客**。选技术栈只是你目前唯一能控制的事情，所以你把它当成了真正要做的事。本质上，你是在用"选择"代替"行动"。

**3. 隐藏约束**
- 你做这个项目的真实动机是"输出内容"，而不是"构建系统"
- 你有一定技术背景（熟悉 Next.js），但技术选择不是你做这个项目的初衷
- 你提到"怕以后不好扩展"——但你没有定义任何具体的扩展场景
- 两周的纠结已经让你疲惫，真正阻碍你的是启动门槛，不是技术风险

**4. 不喜欢的方向**
- 学一个全新的框架来做博客（如果你选择 Hugo，你还要学 Go template 语法）
- 做一个大而全的博客平台（你只是想写，不是想发布产品）
- 把"未来可扩展"作为当前决策的首要标准

**5. 当前核心矛盾**
你想尽快开始写博客，但你用"选择最优技术栈"来替代"开始写"这个让你不安的步骤。技术选择本身没有正确答案能够消除你"害怕写出来没人看"的焦虑。

**6. 可以砍掉的东西**
- "以后想加功能不好扩展"的担忧——博客99%的扩展需求（RSS、评论、搜索、标签页）所有框架都能做，不存在选错就做不了的情况
- 两周对比——你每一篇对比文章都在浪费阅读时间，没有一个决定能值回两周时间
- "大家都在用 Astro"——这是 FOMO，不是需求

**7. 下一步只做一件事**
用你最熟悉的 Next.js，今天之内写第一篇博客文章并部署。不要做主题配置，不要做 SEO 优化，不要读任何性能对比。只写文章。

This is my read of the situation — push back on anything that doesn't land.
