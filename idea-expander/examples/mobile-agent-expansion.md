# Example: Mobile Agent Project Expansion

## Input

> 我想做一个手机端的 AI agent，可以帮我总结微信长聊天记录、提取待办事项、识别对话中的承诺。但我不知道从哪开始，不确定这个想法能不能做，也不确定该做成什么形式。

## Expansion Output

### 1. 当前默认视角
你在以一个产品 creator 的视角思考一个移动端 AI agent 的可能性。

### 2. 本次触发的扩散器
- **risk-preplay** — 因为你说"不知道能不能做"，需要预演失败模式
- **meta-question** — 因为你说"不知道从哪开始"，需要更好的问题来指引方向

### 3. 扩散结果

#### risk-preplay
1. **隐私风险**: 微信聊天记录是高度敏感数据。读取、存储、上传的方式决定了这个项目能不能做（合规、信任、技术难度）。如果数据必须本地处理，能力边界会大不同。
2. **膨胀风险**: "总结+待办+承诺识别"是三个不同的 NLP 问题。承诺识别（谁承诺了什么、deadline 是什么）远比其他两个难。一上来做三个，极大概率一个都做不好。
3. **维护成本**: 微信没有公开 API，数据获取依赖 accessibility service 或截图 OCR。这种依赖很脆弱，微信版本更新就可能断掉。

#### meta-question
1. 如果你只能做一个功能（要么总结、要么待办、要么承诺识别），哪个对你最有价值？
2. 最慢、最烦、最可能放弃的步骤是什么？有没有办法人工先做，再决定是否自动化？
3. 三个月后，如果这个项目失败了，最可能的原因是什么？你现在能做些什么来避免那个原因？

### 4. 最值得继续看的方向
- 先只做"总结"功能，本地处理，验证数据获取路径是否可靠
- 在开始写代码前，先用人工方式模拟一遍完整流程

### 5. 不建议继续展开的方向
- 同时做三个功能
- 一开始就考虑商业化、多平台、架构扩展性
- 承诺识别（技术难度远高于其他两个，可以先砍掉）

### 6. 给 idea-auditor 的审查 prompt

请审查上面扩散出的方向，判断：
1. "只做总结"方向是否验证了核心假设？
2. 本地处理 vs 云端处理的取舍合理吗？
3. 这个项目的风险/收益比是否值得投入？
